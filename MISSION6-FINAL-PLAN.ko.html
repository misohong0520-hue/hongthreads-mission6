미션 6 최종 구현 계획서 — HongThreads

목표

Threads 콘텐츠 작성, 트렌드 확인, 벤치마킹 자료 관리와 AI 활용을 제공하는 HongThreads를 AWS에서 운영하고, 실제 데이터의 CRUD·파일 처리를 검증합니다.

핵심 기능 명세

  • 벤치마킹 보관함: 자료 등록·목록·상세 확인·수정·삭제, 폴더 분류.
  • 콘텐츠 관리: 원고·편집 세션·페르소나·댓글 양식 관리.
  • 첨부파일: 이미지·영상 업로드·미리보기·첨부 해제·삭제.
  • 인사이트·AI·계정·제휴 설정과 작업 이력 관리.

데이터와 서버 구성

Next.js·Node.js 서버와 Supabase Database·Storage, Vertex AI WIF를 사용합니다. 19개 테이블의 필드·키·관계는 README와 SQL migration을 기준으로 관리합니다.

자료는 workspace에 연결하고 폴더는 복합 외래키로 관계를 관리합니다. 첨부는 서버에서 소유권·준비 상태·사용 여부를 검사합니다. 자료 변경은 버전을 비교해 충돌을 감지합니다.

CRUD·파일 처리 기준

  • 등록: 서버에서 필수 값·형식·크기·파일 서명을 확인한 뒤 저장합니다.
  • 조회: 목록과 상세 데이터를 실제 저장소에서 읽고 빈 목록·없는 자료를 구분합니다.
  • 수정: 변경 내용을 저장하고 새로고침 후 유지 여부를 확인합니다.
  • 삭제: 자료·화면 반영과 미참조 첨부 정리를 확인합니다.
  • 오류: 400 입력 오류, 404 없는 자료, 409 수정 충돌, 413 크기 초과, 415 파일 형식 오류를 구분합니다.

공개 접근과 비밀정보 관리

공개 검토 환경은 별도 로그인·비밀번호·쿠키 입력 없이 연결된 화면을 제공합니다. 같은 검토용 자료를 공유하며 요청 검증용 토큰은 브라우저별로 분리합니다. 서버 연결 정보는 암호화하여 보관하고 저장소와 문서에 비밀값을 기록하지 않습니다.

AWS 배포

배포 주소는 https://hongthreads.hongsik.blog입니다. AWS EC2에서 Nginx HTTPS와 두 systemd 서비스를 사용합니다. 릴리스 디렉터리와 current 링크로 버전을 전환하고 검사 실패 시 직전 버전으로 복구합니다.

QA와 문서화

  • 빈 값 또는 잘못된 형식 제출.
  • 등록 후 목록·상세 반영.
  • 새로고침 후 데이터 유지.
  • 수정·삭제 후 화면 반영.
  • 존재하지 않는 상세 데이터 주소 접근.
  • 파일이 없거나 업로드에 실패한 경우.

시나리오별 방법·기대 결과·실제 결과를 QA 체크리스트에 기록합니다. README에는 서비스 소개, 핵심 기능 명세, 테이블 구조, 실행 방법, 환경변수 이름, 배포 URL과 QA 결과를 정리합니다.
